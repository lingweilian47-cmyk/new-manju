# New Manju 漫剧工作流

使用本技能前，先读取插件根目录的 `../../SKILL.md`。该文件是完整总控规范；本文件只负责入口识别与路由，不替代总控正文。

## 输入路由

根据用户当前提供的材料，只进入一个阶段：

1. **只有小说原文、当前 Canon 与用户约束**
   - 读取 `../../references/novel-entry/01_Chat原作影视化增补.md`。
   - 只制作 S1 原作影视化母稿。
   - 用户确认并冻结前，不进入 S2。

2. **已有用户确认冻结的 S1**
   - 读取 `../../references/novel-entry/02_Chat抖音剧情优化.md`。
   - 只制作 S2 抖音版单集事件稿。
   - 用户确认并冻结前，不进入 S3。

3. **已有用户确认冻结的 S2，并可按需回读 S1**
   - 读取 `../../references/novel-entry/03_Chat基础分镜架构.md`。
   - 只制作 S3 基础分镜方案。
   - 不写最终 Prompt，不重新挑剧情，不修改确认对白。

4. **已有冻结的 S1、S2、S3，并准备交给 Work／制作端**
   - 依次读取：
     - `../../references/novel-entry/04_小说漫剧已改编入口与Work交接.md`
     - `../../references/novel-entry/05_Work技术施工与Seedance2.5无时间码流程.md`
     - `../../references/novel-entry/06_Seedance2.5七段式无时间码合同.md`
   - Work 只负责资产引用、人物距离、Blocking、精确景别、机位、构图、运镜、表演施工、内部容量与生成组、Seedance 2.5 Prompt 和 QA。
   - 最终提示词必须使用七段式，并禁止时间码、数字秒数、镜长、总时长和“停顿几拍”。

5. **输入是故事想法、梗概、普通剧本、广告片或其他非小说三阶段任务**
   - 使用 `../../SKILL.md` 中保留的原项目完整入口与 P0-P5 流程。

## 权威边界

- S1 是人物、情绪、动作依据、物件因果、能力与特效机制的权威。
- S2 是单集范围、事件顺序、确认对白、场景体验和节奏的权威。
- S3 是镜头数量、镜头功能、主要观看对象、同框／拆镜和切镜理由的权威。
- Work 是技术摄影、空间、人物距离、生成组、Prompt 执行语言和 QA 的权威。
- 下游发现上游缺口时，必须返回对应阶段，不得静默修改。

## 交付纪律

- 每个阶段只交付该阶段定义的正式工件。
- 保留版本号、基于版本和冻结状态。
- 对原作补充必须可追溯；不得以影视化、抖音节奏或制作方便为理由新增主要剧情。
- 需要校验最终提示词时，运行：

```bash
python ../../scripts/validate_prompt.py <提示词文件> --model 2.5 --profile novel-2.5-ntc
```

- 用户的明确要求优先于示例与可选方法，但不得绕过事实、版本和阶段边界。
